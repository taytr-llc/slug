contract is evidenced. It introduces no runtime behavior or product policy.

The packaged helper exercises both published wallets, real normal-PoW loopback
nodes, automatic live candidate portraits, continuation after a canonical block

reset-held mining and recovery-export refusal, and owned process/listener drain.

Lost-acknowledgment coverage is composed from three explicit boundaries:

1. Set 39's actual two-wallet normal-PoW acceptance loses an admission
   acknowledgment and recovers the identical durable receipt after real job
   expiry, with nodes offline and the current service target changed.
2. Set 40's focused worker observer test first receives an unknown outcome,
   then the retained historical result. It verifies a single notification only
   after the accepted record is synchronized, with original birth intact and
   no duplicate notification.
3. Set 40's actual packaged helper reopens the retained authority/outbox and
   cold-verifies the exact historical records and portrait bytes while stopped,
   without new mining attempts or admission work.

The packaged helper does not inject a lost HTTP acknowledgment itself. There
is no runtime fault-injection option added to the app. The focused observer
test and the independent review must pass before this combined evidence is
accepted. Final packaged source/binary hashes and cleanup assertions are still
required. GUI visual rendering, actual screen-reader checks and the joint D74
