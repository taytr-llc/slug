# Candidate event seed evidence — set 45

`gymseed` connects a complete set 44 noon snapshot to a signed declaration,
its first qualifying publication block and the fixed following block. It
retains the exact evidence across restart, account changes, late finality and
chain conflicts. This is a candidate fixture feature, not an official league
or production publication service. D76/D77 and report-only checkpoints remain
controlling; no seed replacement or automatic event cancellation exists.

## Candidate authority and publication

The shared journal is established before the selected Saturday lock. Prepare
requires the genuine immutable snapshot from both configured gyms. The event
key binds its source event, chain and published declaration signer; a signed
alternative for that same event is retained as conflict evidence. Preparing a
declaration sends no transaction.

Only an explicit Publish action may send the retained transaction. The fixed
publisher borrows the running Demo A (`zero256`) node pair; Demo B's chain is
never a fallback. The separate published scalar1 funding identity uses native
SegWit. Its one-input/two-output transaction commits the exact 73-byte
`SLUGSEED` carrier, pays a fixed 1,000-satoshi fee and returns change to the same
fixture identity. The implementation provides no funding, payout, key, address,
fee or arbitrary RPC input. It cannot spend the gym wallet. A fresh journal can
legitimately wait for mature publisher funds; it never mines or funds itself.

Raw transaction bytes and input reservations are durable before dispatch.
A lost acknowledgement remains uncertain; a later explicit Publish may only
resend those same bytes. Reconcile reads the chain and never dispatches.
Account reset holds block Publish and Attest; authenticated reads, Prepare and
read-only Reconcile remain available. The browser supplies only bounded dates,
view IDs, job IDs and history cursors.

## Fixed target, finality and incidents

The scanner begins at genesis and records the earliest qualifying carrier in
canonical height/transaction/output order. If its anchor is at height A, the
only target is A+1. Compact Merkle evidence does not prove carrier payload or
firstness by itself: the adapter checks the full block, transaction bytes and
ordered scan. Batches perform at most eight distinct normal 256 MiB header
hashes, including repeated anchor/target checks, in a 30-second operation.

The explicit candidate Attest action signs only the exact target after at
least 60 descendants and a final canonical membership check of anchor, target
and the captured tip. It uses a published purpose-bound fixture key; it never
reads the operator checkpoint key. These records are candidate seed evidence,
separate from D62 result finality. Signed checkpoints do not influence consensus
or chain selection.

Historical first finality is retained. Current eligibility is reported with the
last verified chain timestamp, separately from local metadata observation time.
Going offline or losing depth strictly above an already finalized target does
not erase history or itself trigger a D77 incident. Anchor/target conflicts are
latched and remain visible even if the old branch later returns.

An event still unresolved or conflicted at the next Saturday noon lock records
its first authorized incident observation. Finality first observed after that
boundary cannot erase the incident that was already due. An absent event may
report escalation due without fabricating a journal record. Incident reporting
never cancels the event or chooses a replacement block.

## Storage, transport and app

The v5 candidate parent installs a separately pinned seed journal with durable
intent and readiness markers. There are at most 256 events, 128 tracked funding
coins, 16 scan restarts and 8 retained conflicts plus an overflow flag. Corruption
or uncertain writes fail closed until reopen. Reservations and original
publication evidence survive scan restarts.

The helper, native bridge and webview retain one bounded job/result allowance.
A helper frame including LF is at most 262,144 bytes; a record is at most 224 KiB.
Seed reserves 256 KiB within the reciprocal 1 MiB shared cache. The native boundary
pins the complete original account view, authority, creation time and event;
terminal job bytes are immutable. Metadata polling uses closed transport
validation and does not run PoW, project fighters, sign or contact a node.
The panel exposes explicit preparation, publication, chain inspection and demo
attestation, with separate delay/conflict/incident and stale-observation copy.

The old route does not acquire seed capability. `--candidate-seeds` requires
all preceding candidate manifest/stable/entry/event flags. Release builds have
normal PoW and omit the scoped `slugtestclock` test tag. Mike's portrait check,
full joint D74 review and actual accessibility/rendering acceptance remain open.

before comparison against set 45 Go output. `freeze.json` binds corpus SHA256
`2b8d78e8ef665e372543eb87bb5d25a975026a0ae946b15a871ac97bbf2153f0`,
inputs, source formulas and exact approved contracts. Both Python versions and

The corpus includes 125 DTOs, 1,420 codec cases, 194 protocol cases, 3,861 Saturday
rows, 78 retained record states and 69 full wire-block fixtures. Its modeled
state transitions are not filesystem, process or node executions. Synthetic
block inputs are not a consensus-admitted chain. Actual crash, ownership,
normal-node maturity/relay, reorg, native-pipe and packaged tests remain separate.

not claim that set 45 is deployed or accepted before those gates pass.
