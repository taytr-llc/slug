Root approved implementation ownership after the three clarifications recorded below; test execution remains separately coordinated. Set65 is complete at `7bf924f6a11f496060633c58623242e18b1e3004`; Set66's old-API public-input extraction currently owns the normal-work lane.

The frozen core contract is `frozen/public-fighter-evidence-v1-contract.md`, SHA256 `16a9166ebe1c7a0f5b0a8d554a043e6a690c29bec7864df9de123fc5cc01f272`. ## 1. One useful action, fixed scope

Add **Export public evidence** to the existing completed fighter-history detail. One control starts export and becomes **Cancel evidence export** while that original operation runs. Reuse that panel's status and polling; add no navigation, import, automatic history capture, wallet access, signing, node observation or automatic result-proof export. Enable the new route for already supported career-enabled solo and explicit shared-pool contexts, using their existing independently established exact source. Do not broaden any old protocol grammar or change old receipt/recovery exports.

Keep the frozen explanation: “Saves the original receipt and this captured history. Offline checks confirm supplied work and record consistency; they do not prove admission time, actual awards, ownership or a complete career.” A successful live export reports a file checksum and byte count. It does not report that the separate offline verifier ran.

The file has exactly `{format,version,admission,capture,rows}`, in frozen order, canonical bytes without a trailing newline. The total cap is 524,288 bytes; the canonical admission cap is 65,536; capture cap is 8,192; at most 256 rows, each at most 1,536. Existing receipt exports may have a different allowance; this new format does not inherit their larger limit. No path, destination pin, ViewID, session credential, private key, recovery material or native job DTO enters the archive. Permanent public account/gym pseudonyms inside the frozen source and rows remain present.

## 2. Exact private wire family

New family version is 1. All object members below are required, in the stated serializer order; no `omitempty`. Reject duplicate/unknown members, wrong scalar types, null non-nullable fields, out-of-range integers, invalid IDs, unsupported versions and command-inapplicable values before controller dispatch. Parsers may follow the existing closed transport whitespace/order policy; archive canonicality remains a separate stronger rule. Preserve the exact existing full `ManifestViewPin` grammar and its independent v1/v2 descriptor/source discovery.

Limits: request 4,096 bytes, response 8,192, snapshot 4,096, job 4,096, summary 2,048, no raw evidence bytes over IPC. These are encoded-byte bounds, so a valid native path whose encoded request exceeds the request bound is rejected before dispatch with no output mutation. Request and response correlation IDs are integers in **1..9,007,199,254,740,991 (MaxSafeInteger)**, matching existing closed desktop families; zero and larger uint64 values are rejected. Web DTO integers follow existing safe-integer limits. All digest/operation/history/view IDs use the existing canonical 64-character lowercase hex grammar.

### Request

```text
FighterEvidenceRequest {
  id: uint64,
  version: 1,
  command: string,
  view_id: string,
  history_job_id: string,
  history_id: string,
  job_id: string,
  selection: recoveryfile.Pin | null
}
```

`job_id` is the new export operation ID, **generated by native from 32 random bytes before sending begin**, not allocated only in the helper's acknowledgment. It is unrelated to `history_job_id`. It is an opaque correlation token, never authority. Native retains it with the original full view/history tuple and selected destination. This makes a lost begin response recoverable without asking for “the latest job.” Entropy is obtained outside account/controller leases. A caller cannot substitute a different token after the operation begins.

| Command | Required nonempty fields | Other fields |
| --- | --- | --- |
| `fighter_evidence_snapshot` | none | `view_id` may be the exact current view or empty for discovery; history/job strings empty, selection null |
| `fighter_evidence_begin` | view_id, history_job_id, history_id, job_id | selection is an exact create-only Pin; no other payload |
| `fighter_evidence_job` | view_id, job_id | history strings empty, selection null |
| `fighter_evidence_cancel` | view_id, job_id | history strings empty, selection null |

Create Pin is the unchanged Set62 shape: version 1, mode `create`, canonical path, exact parent device/inode, `file:null`. There is no additional plain path argument. Begin refuses an already-used retained operation ID; it never treats a repeated begin as permission to republish or choose another destination. Native never automatically retries begin. Lookup is the only recovery operation after an uncertain acknowledgment.

### Response

```text
FighterEvidenceResponse {
  id: uint64,
  version: 1,
  ok: bool,
  snapshot: FighterEvidenceSnapshot | null,
  job: FighterEvidenceJob | null,
  error: string
}
```

Successful snapshot selects only snapshot. Successful begin/job/cancel selects only job. Errors have `ok:false`, both payloads null and one bounded code. A final original-view check is required before every nonblank payload disclosure. A completed mutation followed by revoked disclosure returns no old-view payload.

```text
FighterEvidenceSnapshot {
  version: 1,
  state: "unavailable" | "idle" | "busy",
  error: string,
  view: ManifestViewPin | null,
  store_id: string,
  active_job_id: string,
  last_job_id: string
}
```

Unavailable is completely blank (`view:null`, empty store/job IDs) with error exactly `evidence_unavailable`. Stale-view, unauthorized, forbidden and other authority failures are envelope errors with no snapshot or job payload; they are never alternative unavailable-snapshot error strings. Idle/busy have the exact current full view and stable store ID, empty error. Busy requires active_job_id; idle requires it empty. last_job_id is empty or names the last terminal operation in that same view. There is no queue and no queued-job field.

```text
FighterEvidenceJob {
  version: 1,
  job_id: string,
  state: "running" | "done" | "failed" | "cancelled",
  view: ManifestViewPin,
  store_id: string,
  history_job_id: string,
  history_id: string,
  prospect_id: string,
  error: string,
  summary: FighterEvidenceSummary | null
}

FighterEvidenceSummary {
  version: 1,
  file_sha256: string,
  file_bytes: uint32,
  prospect_id: string,
  history_id: string,
  source_record_digest: string,
  event_count: uint32,
  captured_as_of_ms: int64
}
```

The immutable job tuple is job ID + full original view + store ID + original history job ID + HistoryID + ProspectID. Internally also pin the selected capture hash, assignment, activation, opaque history-handle identity/epoch and full expected stable Pin. Retain the destination pin/hash internally; never echo it to the browser. Summary values must match that tuple and captured assignment/count/time. `file_bytes` is 1..524,288 and event_count 0..256. The summary has no `checks`, `unverified`, certificate, archive ID or offline Report fields. The source/descriptor identity is already in the independently correlated view/store and original selected capture.

Running has empty error and null summary. Done has empty error and exact summary. Failed has a terminal error and null summary. Cancelled has `evidence_cancelled` and null summary. Terminal objects are immutable and published only after work and file cleanup have joined; do not publish done and later revise it after a failed close.

Retain at most one active job and one last terminal metadata-only job per controller. No extra capture or raw archive is retained in terminal metadata. A new begin may replace the old terminal slot only after native has resolved its preceding begin/handoff; the native pending-operation slot prevents another begin while acknowledgment is uncertain. A same-process lookup after a complete framed begin has returned and before any intervening begin can definitively report `evidence_not_found`; an arbitrary later not-found is not proof that no prior file was published.

### Closed error vocabulary

Request/disclosure errors: `invalid_request`, `stale_view`, `unauthorized`, `forbidden`, `busy`, `history_not_found`, `history_unavailable`, `evidence_not_found`, `evidence_capacity`, `evidence_operation_conflict`, `evidence_unavailable`, `evidence_profile`, `outcome_unknown`.

Terminal failures: `evidence_invalid`, `evidence_source_changed`, `evidence_unavailable`, `evidence_destination_conflict`, `evidence_storage_failed`, `evidence_export_uncertain`. Cancellation uses only `evidence_cancelled` after definite prepublication cancellation and joined cleanup. Capacity is rejected before admission, so it is not a late terminal failure. Ordinary cancellation before publication must not be represented as successful output.

`outcome_unknown` is dispatch/disclosure uncertainty, not a blanket claim that a file exists. It triggers lookup of the already known operation ID or a joined shutdown. `evidence_export_uncertain` specifically means exclusive publication may have happened but final durability/authorization acknowledgment could not be established. Once a possible link occurred, cancellation cannot downgrade that result to cancelled. A transport loss during begin can leave dispatch unresolved and therefore also leave eventual publication possible; UI must first say “Checking whether the export started.” If exact resolution is impossible, use “The export could not be confirmed. Check the selected destination before trying again.” A known publication uncertainty uses “The evidence file may already be saved. Check the selected destination before trying again.” No raw error, path, file contents or secret enters any message.

## 3. Native selection and acknowledgment ownership

Proposed exported native methods:

```go
BeginFighterEvidenceExport(viewID, historyJobID string) (*pilot.FighterEvidenceResponse, error)
FighterEvidenceSnapshot() (pilot.FighterEvidenceResponse, error)
FighterEvidenceJob(viewID, jobID string) (pilot.FighterEvidenceResponse, error)
CancelFighterEvidence(viewID, jobID string) (pilot.FighterEvidenceResponse, error)
```

Dialog cancellation is `(nil,nil)` from begin and creates no helper operation. Frontend cannot supply raw source trust, history rows, HistoryID, export job ID or destination. Native derives those from its verified selected-history correlation and fresh operation ID. Before displaying the dialog, require the browser's view/history job to match the currently selected completed native history job; capture its full view, original HistoryID, ProspectID, assignment and activation. After the dialog, never look up a replacement capture or the current child and silently use that instead. The helper rechecks that original tuple after the handoff.

Hold `exportMu` only across native selection and synchronous begin handoff. Save dialog default name can be `slug-fighter-evidence-<public-id-prefix>.json`. Use the existing protected-root set and create-only native `recoveryfile.Capture`. The native Selection remains open until the helper has synchronously opened and verified its own matching directory handle, admitted the same operation, and returned a valid acknowledgment. No raw archive or selected file is read by native.

The helper's successful begin response means **destination ownership and background dispatch were accepted**, not “file saved.” The job may already be terminal by the time the response arrives, but its terminal semantics still apply. Definitive framed refusal means begin finished without asynchronous ownership; native closes its Selection. Accepted dispatch transfers operation ownership to helper, which holds its directory handle through completion/cleanup; native can then close its duplicate Selection.

If transport prevents knowing whether begin finished, retain exactly one native pending Selection, bound to helper instance + original private request ID + known export job ID + original full view/history tuple + canonical selection digest. Release `exportMu` so logout/reset/quit remain possible; only another evidence begin remains unavailable. Do not drop this descriptor merely because the IPC deadline elapsed. Resolve by lookup of this exact job on the same helper, a fully ordered framed no-admission response with no intervening begin, acknowledgment that the original child has been cancelled and joined during logout/reset, or observed helper termination. Never use whichever active/last job appears in a snapshot as a substitute. A stale-view lookup alone does not establish descriptor ownership or cleanup. If cancellation of the native action prevents a safe ordered query, retain the one slot until joined old-child cleanup or helper termination. No detached background open is allowed after a definitive refusal.

The native bridge serializes its exact family using the existing private-channel gate. PoolBridge must route explicitly through pool source discovery; do not fall back to an embedded solo method. Native cache consists of bounded job correlation/terminal checksums and the one pending descriptor; it does not duplicate the history rows or archive. Snapshot/job response acceptance verifies the immutable tuple and terminal immutability, including after lost acknowledgment.

## 4. Admission, work and publication lifecycle

Use the existing `gymaccount.View` capability and original account-generation/view publication lease. A newly authenticated security-held session may export this public data. Revoked old credentials cannot finish. Never use RecoveryExport, current-login substitution or a lease held over proof, source read, serialization, entropy, directory opening, temp write, wallet or network work.

Admission order:

1. Cheap closed request validation and exact original-history selection. Require a completed existing opaque history handle, matching original job/HistoryID and current original view. No implicit `BeginCareerHistory` or recapture.
2. Fail-fast acquire the parent-owned evidence permit and its accounted scratch reservation before source read, filesystem preparation or serialization. **Mining must be stopped, the stable lane idle, and no backup active.** Serialize admission with the same child lifecycle/start gate, then recheck the entire worker run lifetime and original-view state at final admission; a gap between automatic hashes is not stopped mining. Return definite `busy` without admitting work if mining or a lane task is active. Do not pause, stop, resume, enqueue behind or otherwise change mining. The existing panel says “Stop mining and wait for the current task to finish before exporting public evidence.” Snapshot metadata can show running once ownership is admitted; there is no waiting export queue.
3. Open/verify the pinned destination synchronously outside account/controller leases. Capture deadline and cancellation linked to the helper/child lifetime, not merely the begin-RPC lifetime. Any definite failure closes the opened handle and releases the reservation before refusing begin.
4. Under the short original history-publication lease, recheck exact child/view/generation/handle/epoch, active state and reservation ownership; install the immutable running job and transfer owned directory handle to the background task. No async Open after acknowledging dispatch. If admission occurs but final response disclosure fails, preserve the admitted job and resolve it by its preknown ID; do not roll back by assuming nothing ran.

Work deadline is 30 seconds from reservation, with context checks before each phase. Existing proof verification is uncancellable once entered: cancellation waits for that single call, suppresses later publication and joins cleanup. The deadline is not a measured hard runtime bound for an entered proof or filesystem syscall. Do not detach proof goroutines or release their reservation early.

The operation obtains the exact selected receipt through the new narrow concrete `gymstable` accessor over the original opaque history read, outside account leases. That accessor performs one verified source read, matches the complete original assignment (including Pin2's original global source sequence), and supplies owned receipt/capture/rows. Pages retain the same capture; receipt-cache eviction and fighter age outside the last eight display rows do not affect correctness. No JSON-to-authority constructor or source copying is introduced. Read all 0..256 captured rows or fail; never truncate.

Call the cheap `fighterevidence.Marshal(expectedPin, archive)` after that one verified source read. Do not call `VerifySupplied` in the live export and hash the same proof again. The expected pin is the controller's exact already trusted source, not copied out of claimant JSON. Source replacement/rollback/closed/poisoned state, changed history handle or changed account view refuse. New global rows do not replace the selected capture.

The export task owns the lane/source lifetime while reading. Do not call top-level `CareerHistoryPage` while already owning `laneGate`; use the shared internal reader/underlying store path. Existing `BeginCareerHistory` clears the previous handle, so it is not an unchanged template for export admission. Export admission must preserve the selected handle until its own operation joins.

Bulk canonical serialization, whole-file SHA256 and temporary write/fsync happen outside the original account lease. Final exclusive publication is the only filesystem mutation under the short original View fence: recheck original token/generation/child/history handle/epoch, operation/reservation identity, context and pinned destination parent; link the already synced temp exclusively; sync the directory. No large copies, source reads, proof checks, entropy or async callback occur inside that fence. Preserve the exact-once callback and uncertain-write rules of existing guarded publication.

## 5. Standalone public staging writer

Add a separate private desktop public-file staging package/helper. Reuse the existing create Pin grammar and native Selection; reuse or factor only safe shared directory primitives, without changing old recovery behavior or increasing `recoveryfile.MaxSize` (65,536). The new writer has its own fixed 524,288-byte cap and no read/import/recovery API.

Conceptual API:

```go
Open(pin recoveryfile.Pin, protected []string) (*Handle, error) // sync pin acquisition
(*Handle).Stage(ctx context.Context, raw []byte) error          // bounded temp write/fsync
(*Handle).Publish(ctx context.Context, fence recoveryfile.Fence) error
(*Handle).Close() error                                       // joined temp cleanup/descriptor close
```

Open accepts only create mode, verifies canonical pinned parent and forbidden destinations, and owns a directory FD. Stage uses a random exclusive 0600 temp in that directory, bounds bytes before copying/writing, writes exact canonical bytes, fsyncs and closes the temp outside the account lease. Publish uses the retained directory and temp identity; it never overwrites an existing final destination and never follows a replacement path. Existing destination is a definite conflict. A directory move/replacement fails the original-parent check; descriptor ownership is never inferred merely from the path still existing.

After possible exclusive link, a failed directory sync, final account recheck or lost local completion acknowledgment yields publication uncertainty. Never remove or overwrite the published final path, and never automatically choose a second filename. Clean the unlinked staging name and close all descriptors on every path; cleanup failure is preserved, not swallowed. Produce done only after all relevant cleanup/close succeeded. If cleanup cannot establish a clean reusable owner, latch that owner unavailable and fail Close visibly; do not admit further exports into an unbounded accumulation of orphan temp files. OS-handle work must be joined even when cleanup reports failure.

## 6. Explicit capacity and cross-child ownership

There is **one active export owner per account parent**, shared across all its old/current/replacement child generations, and at most one in any child controller. A directly instantiated legacy standalone controller owns its own one-owner gate. Native also permits one unresolved selection/handoff per helper instance. These gates are fail-fast with no queue. This is per-parent/controller capacity, not a claim of a single global process owner across separately created applications.

The parent reserves exactly **4,194,304 accounted scratch bytes** for the admitted export before source/serialization work. This is an accounted allowance for detached receipt/capture/rows, canonical buffers, encoding copies and staging buffers; it is **not a measured hard Go heap cap**. Implementations must enumerate their retained copies against this allowance and independently enforce the actual component and file byte bounds. Release only after the one proof (if entered), canonical/hash work, file publication and cleanup/Close have joined. UI blanking, lost acknowledgments, child pointer replacement and logout cannot release or duplicate it early.

The old `MaxManifestCacheBytes` 1 MiB and `careerHistoryAllowance` 512 KiB remain unchanged. The export allowance is separate because a maximal archive plus retained history does not fit the old shared-cache ceiling. Terminal export metadata is bounded separately to two small job slots, with no retained archive bytes. No whole new copy of the captured history is hidden in native or terminal caches. Parent shutdown waits for its permit owner outside account/controller locks; it cannot close borrowed stores or create a successor owner first.

## 7. Cancellation, reset and backup

`fighter_evidence_cancel` signals only the known operation in its original view and returns its current correlated job. It may still be running while an entered proof or cleanup joins; do not return a terminal cancelled state early. Polling resolves the terminal result. A duplicate cancel is safe and cannot publish again. An already done/failed/cancelled job remains byte-stable.

Logout, verified reset, expiry, view replacement, Stop and Close cancel and **join** the owned export before destroying its source/handle or admitting a successor child. Joins occur outside account and parent mutexes. Source closure cannot race an abandoned proof. Hold the parent permit across the entire old-child drain, and preserve the no-payload-after-revocation fence.

Backup admission keeps the existing `PoolChild.stopMu` sequencing: mark/reserve the backup under a short original lease, cancel active export/lane work, then drain outside account leases before opening wallet/restore work. Export finish/cleanup must not acquire stopMu, otherwise backup/Close would deadlock waiting for it. Export start during backup or any active mining run fails busy; Start mining during active export also fails busy. Export admission and Start share the lifecycle gate so neither can slip between the other's preflight and reservation. This action never implicitly starts or stops mining. Existing history replacement/invalidation cancels and joins an active export or reports busy; clearing UI/history bookkeeping alone cannot free its handle or reservation. Existing ordinary history, lane and backup behavior remains unchanged when no export is active.

## 8. Implementation ownership proposal

- Core and live accessor owner: frozen archive codec/verifier/CLI; additive concrete history extraction in gymstable; one verified source proof plus cheap Marshal; no desktop-specific IDs in archive. Independent reference artifacts remain distinct from observations.
- Desktop child owner: `desktop/pilot/fighter_evidence_{types,controller,validation}.go`, narrow history/lane internal hooks, PoolChild forwarders, accounted reservation lifetime and backup/Stop/Close integration. Coordinate declarations before shared-file edits.
- Parent/protocol/native owner: `desktop/accountpilot/fighter_evidence.go` and pool forwarding, exact original publication callbacks, closed wire marshal/parse/dispatch, bridge correlation and explicit pool discovery, `desktop/fighter_evidence.go`, standalone staging writer and descriptor handoff. Parent owns the cross-generation permit; child receives a borrowed capability, not a new gate.
- Frontend owner: one existing-history action and bounded exact summary/status validation, v1/v2 exact source correlation, original view before dialog, fixed limitation copy. No layout or navigation redesign.

Potential exported surface (names frozen only after root review): `FighterEvidenceSnapshot(ctx)`, `BeginFighterEvidence(ctx, viewID, historyJobID, historyID, jobID, selection)`, `FighterEvidenceJob(ctx, viewID, jobID)`, `CancelFighterEvidence(ctx, viewID, jobID)`. New `FighterEvidenceSurfaceAPI` composes into supported career surfaces; unsupported modes refuse before touching destination or stores. Helper begin synchronously takes descriptor ownership, then returns the running/terminal metadata. The browser/native APIs do not accept the selection as a web argument.
