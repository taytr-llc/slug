# Shared fixture event and career cycle

Set64 attaches the existing seed, card, bout, result and career authorities to
the Pool Pilot's concrete shared runtime. The two published fixture gyms keep
their original source, Pin2 stable identities, global receipt sequences and
entry/event history. The existing interface panels are reused. This is candidate
engineering; production accounts, ownership, permanent genesis and the final
joint D74 design review remain separate work.

## Durable ownership and activation

The parent owns the event chain of stores and the live career reader. Its new
`shared/event-cycle-v1` directory contains `seeds`, `cards`, `bouts` and `results`,
immutable `INTENT.json`, component completion records, `ACTIVATING.json`,
`ACTIVATION.json` and `READY.json`. The existing Set63 league markers are unchanged.
Each stage pins its exact upstream store ID, creation time and complete source
authority. Missing established stores or guards fail closed; startup cannot
recreate lost history or adopt an unrelated directory.

Result career accounting activates before any child can operate and before its
first finalized result. The same activation is durably bound into both original
stables and the shared card. An interrupted activation resumes only that exact
recorded intent. On restart, career-aware bootstrap opens guarded stables and
the card with the expected activation before reconstructing the result reader;
the live reader attaches before publishing any child view. An unavailable reader
never means zero records or zero XP.

Activation cannot be backdated. A Set63 snapshot whose cutoff predates the new
career activation remains historical evidence; it cannot be retroactively booked
through this career authority. New events must lock after activation. D76 still
freezes roster, assignment, eligibility and condition at noon Pacific. Effective
career awards at that cutoff supply XP; later finality never rewrites the earlier
snapshot.

## Concrete shared-chain publication

`seednode.AttachSharedPool` and `AttachSharedPoolResult` borrow the actual parent
node pair. Their trusted binding includes concrete account/issuer/event handles,
complete shared source and event identities, original process handles and runtime
lifetime. Marker hashes come from the parent's already validated retained public
objects; reading a file and hashing it is insufficient to establish authority.

Both event participants must be the fixed fixture gyms with Pin2, the same
issuer and the same account authority. Strict command/configuration checks retain
the existing loopback topology and genesis/activation checks. Only the shared
primary permits its exact eleventh `txindex=1` configuration line; the legacy
ten-line owner contract is unchanged. Every shared operation rechecks its concrete
owners and configuration, including after RPC reads before disclosing outputs.

Publisher borrows remain bounded to thirty seconds and eight distinct normal-PoW
header checks. The issuer's additive `TryInfo` permits context-aware handling of
temporary contention: only its busy response retries, outside account/event
leases and within the existing request, borrow and runtime lifetimes. The old
blocking Info API is unchanged. Process exit, runtime cancellation,
closed source, changed marker, wrong configuration or a replaced authority makes
the borrow unavailable. Closing a borrow cancels and joins its work without
stopping the parent nodes.

The seed publisher spends only the existing public scalar1 fixture outputs;
the result publisher spends only scalar2. Pool settlement uses scalar3. Each
publication retains its one input, fixed 1000-atom fee and same-script change,
with exact bytes and reservation durable before broadcast. A retry uses those
same bytes. Setup, login, reconciliation and publication never create mining
jobs or fund themselves. An unfunded publisher visibly waits for separately
provided mature outputs. Pool rewards, fee balances and player wallets do not
fund these carriers implicitly.

## Finality and career behavior

The event seed remains the exact target fixed by its published carrier. Genuine
canonical membership, its purpose-bound fixture checkpoint and sixty descendants
are required; calendar advancement supplies no chain depth. D77 delay and incident
reporting remain in force without replacement seeds or automatic cancellation.

C1 still permits only the scoped two-gym, same-class, zero-record candidate
pairings inside the inclusive half-to-double rating band. Cards retain entered,
paired and unmatched counts and reasons. General matchmaking, ranking and title
selection policy is not expanded by this integration.

A saved bout remains provisional through publication and inclusion. Its own
result checkpoint and sixty descendants activate records, XP and implemented
base points exactly once under D78. Replay, lost acknowledgment and restart do
not grant another award. A later reported conflict preserves the official award
under D62. Base points are labeled as history, not a completed ranking system.
Already-awarded fighters cannot use C1's zero-record entry path for a new entry.
Eligibility is checked when applying an entry and again at its noon cutoff.
Pre-enrolling before an award does not grandfather a fighter into a later C1 card;
an ineligible pending intent can be explicitly abandoned without changing the
previously saved entry. The earlier frozen noon snapshot remains unchanged.

## Original views and interface boundaries

Children borrow all downstream stores and own their stable/entry handles and
bounded operation lane. Original-session capabilities fence dispatch, commits and
disclosure; no account lease spans RPC, hashing, store audit or shutdown joins.
Logout/reset closes the child after draining work while the parent authority
survives. Runtime shutdown closes children before results, bouts, cards, seeds,
events and their shared issuer/nodes.

Each existing seed/card/bout/result/career/history family has an explicit narrow
pool surface. Native preparation walks actual PoolSnapshot and Pin2 authorities
through the complete source chain and rechecks the original view at the final
pipe gate. It never falls back to a solo manifest context. Existing closed
grammars, per-family byte limits, page bounds and opaque career read handles stay
in force.

Result snapshots identify live shared nodes as `shared_pool`, accepted only
with the matching Pin2 authority. Pool controls cannot spawn or disconnect the
parent node pair. Only explicit Start begins mining. Backup blocks new lane
dispatch, drains active operations outside account leases, and leaves job polls
and cancellation available. Recovery still retains its own original capability
and hold restrictions. Practice previews remain unavailable in the shared route.

Qualification uses separate normal-package and tagged calendar tests. Neither
fixture-key evidence nor an automated interface check replaces production custody,
release signing, hosted operations or the thorough design review with Mike.
