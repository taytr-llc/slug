## Change and purpose

The shared Pool Pilot now attaches its original two gyms and noon coordinator
to the existing seed, card, bout, result and career authorities. One parent owns
the full pipeline and activates career accounting before exposing children or
accepting the first finality. Existing Set63 source identities and older solo
namespaces remain intact. See `SHARED_EVENT_CYCLE.md` for the durable contracts.

The publisher borrows the actual parent node pair through concrete live owners,
complete source pins and validated retained marker identities. It preserves the
thirty-second lifetime and eight-header normal-PoW work budget. Seed and result
carriers use separately funded public fixture scripts; neither pool rewards nor
player wallets are silently spent on publication. No action starts mining except
the existing explicit Start control.

The existing panels expose shared seed preparation/publication, fixed-seed cards,
saved fights, provisional results and finalized careers. Native dispatch and
helper protocols preserve original-view authority through the entire source
chain. Recovery drains active operations and blocks new work without disabling
polling or cancellation. Shared practice remains unavailable. There is no layout,
navigation or logo redesign.

## Retained failures and corrections

Every attempt remains in the artifact directory. Earlier component attempts
include sandbox listener denial and a test fixture's invalid seed-node state.
The first frontend run exposed fixture namespace adaptation and outdated
expectations; production authority was not loosened to satisfy them.

The first full actual cycle reached seed publication and genuine height123,
then failed a same-tip reconcile. Read-only inspection established that the
carrier landed in block123, leaving its required successor unmined. The harness
now follows observed inclusion with bounded explicit mining rather than assuming
two blocks always supply both inclusion and successor. An instrumented run on a
copy of the retained fixture reproduced the separate reconciliation error:
`ManifestStore.TryInfo` returned its expected busy response during a background
read, which the shared publisher had misclassified as unavailable. The narrow
fix waits only for that contention, within the existing context and runtime
limits; all source mismatches and substantive failures remain refusals.

Review also corrected previously unreached harness expectations: C1 checks
eligibility at entry Apply, not intent Prepare, and pre-enrollment does not
grandfather an awarded fighter into a later C1 noon snapshot. Refused intents
are explicitly abandoned and the original saved entry remains unchanged.

The second full actual run reached genuine seed and result finality at height238,
then stopped on another harness representation error: saved bout results contain
the full winner ID or an empty draw, while the separate pure career-arithmetic
API accepts corner labels. The expectation now maps the saved ID against the
exact card corners and retains independently stated XP/point values. No production
code changed. The third full run passed the remaining replay/restart and C1-refusal checks.
The second run remains failed; it is not relabelled as full acceptance.

Package checker attempts retained a preflight test-source delta and the previous
Set63 before-noon oracle. With active career authority, the exact refusal is
`career_unfenced`, before any cutoff mutation. The successful checker verifies
that refusal and unchanged event state. These were checker corrections, not
production relaxations or GUI acceptance. A sandboxed package build also failed
at iconutil; its logs remain, and an unchanged-source escalated build passed.
The first focused-core runner omitted the calendar tag and ran only one of
four intended tests; its scope assessment is retained, and the corrected runner
requires an explicit passing row for all four tests.
The final qualified bundle is `package-attempt3/SLUG Pool Pilot.app`; its only
later code delta is the tagged integration-test winner correction, excluded
from the normal application build.
