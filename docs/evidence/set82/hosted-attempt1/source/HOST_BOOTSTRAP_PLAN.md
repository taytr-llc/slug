# Fresh bounded hosted-test bootstrap

Source-only proposal, 2026-11-21. No host, volume, credential, database or deployment was accessed or changed. This prepares the existing finite operator; it changes no payout, capacity, custody or recovery rule.

## Smallest bootstrap

Use a **separate admin image**, built from the same pinned public source/binaries, for the fresh operator test volume. Keep the qualified scratch operator image unchanged. Its only root action prepares an exact new subtree, then it drops both real/effective UID and GID to10001 and enters a fixed1800s idle window. This lets root select the real UTC due after images/node/routes are ready. Explicit SSH commands run fixture preparation and original init/rotate as10001; the admin deployment then stops and is replaced by the scratch image. It must not run an SSH daemon, listener or permanent root wait loop. Provider SSH may default to configured USER0, so each preparation command explicitly selects and verifies10001 rather than inferring its UID from PID1.

Railway SSH is enough to invoke an existing fixed command, but is unnecessary for uploading files: bake an explicit hash/length allowlist of **already published fixture source/reference inputs** into the admin image. Never include a developer home, previous actual-run tree, prebuilt wallet/runtime database, real key, offline recovery directory or checkpoint signing key. Do not turn `slugpool-provision` into a deterministic-seed importer. Its existing create command intentionally uses OS entropy and is the separate real-operator custody path.

The one packaging addition is a fixture-only `prepare` entrypoint, reusing the published `fixture_setup.go` wallet constructor and exclusive protected-file writer. The current actual helper is not that command: its main also launches nodes and relays. The new entrypoint must only validate its fixed public selection, materialize the selected fixture inputs, call original `wallet.CreateDailyPoolSettlementWallet`, close the wallet, and emit public identities. It must never run the old actual scenario implicitly. Root reviews/builds this small adapter before any execution.

## Endpoint and fixture prerequisites

Choose the raw-TCP public endpoint and certificate hostname before materializing Setup, issue profile, remote config or credentials. Generate the test TLS private key inside the protected preparation owner; only the public certificate/SPKI belongs in the public record. The inherited certificate helper covers127.0.0.1 for one hour, so it cannot be used verbatim for a Railway hostname or an unbounded test window. Keep the same original hostname/CA/SPKI validation; this is a fresh fixture selection, not repinning an established wallet or history.

Recommend **one hosted ordinary PhaseA node, the original copied Mac fixture peer, and the unchanged standalone operator**, each process non-root, with no `localwalletpilot` flag. Preserve the exact existing public height2 prefix: submit root-exported original raw blocks1/2 to a fresh hosted node, then generate60 genuine normal blocks to62 and require the Mac peer to synchronize that exact history. This avoids copying node databases or reorging the existing fixture wallet onto newly invented blocks1/2. Configure connect-only peers, `nodnsseed`, private HTTPS RPC, transaction indexing and the fixed public fixture mining address. The three reference JSONs do not constitute an identified raw baseline-block export; root must bind the separately exported public bytes/hashes. The deployed seed and checkpoint policy are unchanged.

Root selected a fixture-only mTLS P2P relay to enforce this peer boundary. Host TLS29333 requires a fresh private client certificate and exact selected leaf, then forwards only to node loopback29334. The Mac bridge listens only on127.0.0.1:29489 and verifies the remote hostname/CA/server SPKI before forwarding. Both relay directions close and join on shutdown; the host relay owns the original node child, TERM30s then KILL5s with timeout retained as failure. Fresh transport private keys are protected, never deterministic public fixture keys or image contents. The operator image still has no supervisor; this small node-image owner exists solely to close the otherwise public inbound test-chain exposure.

This is source-feasible, not yet host-qualified: MainNetParams already permits normal `generate`, uses207fffff and has no compiled checkpoints. Original generation uses adjusted current timestamps. `getblocktemplate` requires a connected peer and, above genesis, a tip no older than24h/not behind the sync peer. Existing connect-only mode disables discovered outbound dialing. Root's separate bounded bootstrap check must establish the selected fresh-chain anchor/activation state, original peer readiness and proposal acceptance before starting the worker; explicit fixture bootstrap/maturity blocks must remain distinct from the actual worker's two pool-winning receipts. Do not replace that worker proof with node-generated pool work. An idle node older than24h should fail readiness rather than silently enable the pilot exception.

**The old Set81 node launcher is not reusable verbatim:** it selects `localwalletpilot`, whose P2P and RPC endpoints must be literal loopback. Do not proxy/expose that mode to cross services. A same-namespace supervisor would be additional packaging work and is unnecessary if the ordinary fresh-node arrangement qualifies. Published wallet/authority fixtures remain confined to this disposable isolated chain; they are not custody for the live seed or real funds.

These are concrete packaging/host checks, not requests for new economic policy: selected volume support, endpoint/certificate, UID enforcement, fixture-only materializer, and the chosen node topology must be resolved before the first hosted payout claim. General continuation, hot certificate rotation and extended-offline catch-up remain deferred follow-ups. No new user choice is needed to prepare this bounded fixture plan; real funds or personal custody would be a different task.
