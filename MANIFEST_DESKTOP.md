# Set 40 engineering contract: fixture candidate desktop

Status: proposed exact implementation contract for parent review. The isolated set40 stage exists, but implementation waits for this contract review; this document itself makes no runtime or repository change. This implements the accepted `set40-desktop-proposal.md` on top of the frozen set39 pipeline. It does not activate an official descriptor, register ownership/a roster, migrate custody/providers, calibrate discovery or approve a product release.

## 1. Mode, compatibility and scope

Add the explicit boolean launch flag `--candidate-manifests` to the native shell and bundled helper. It selects mode `local-manifest-pilot`, with default application data basename `LocalManifestPilot`. Without the flag, current launch selection and all current modes remain unchanged. In the helper, `--candidate-manifests` and `--account-fixtures` are mutually exclusive, since the former already includes its own fixture-account controller. Explicit `--data-dir`/the existing environment override remain available for isolated verification; they never authorize adopting another mode's data.

Keep `LocalPilot`, `LocalWalletPilot` and `LocalAccountPilot` untouched. A path containing their markers, a nonempty unrecognized directory, or a nested/ancestor path overlapping one of those established managed roots is refused before creation. All four default application roots plus the active custom root are protected destinations for recovery and public-receipt export. Resolve existing parent directories before containment checks; reject managed-root symlinks and preserve no-overwrite writes.

Use only the existing published `zero256` and `incrementing256` wallets and the current schema1 fixture account provider, account enrollment/recovery challenge, session and 24-hour hold rules. The outer account authority is schema1. Each gym has a **different, separately generated schema5 manifest authority**; its authority ID is not the outer account authority ID. Do not substitute one ID for the other. Use the existing retained wallet's action-specific prospect signer, protected by the existing account mining lease. No schema2 identity assertion/provider journal, recovery vault, delegated custody callback, real keys or new wallet profile is introduced.

The new mode retains the current private two-node normal-PoW topology, Phase-A genesis/rules, legacy fixture payout at account0/branch0/index0, and explicit all-`ff` fixture prospect target. This target remains a public engineering fixture, not a product discovery rate. The candidate descriptor must resolve through `fighterdescriptor.ResolveCandidate`; production resolution remains closed. The fixed descriptor at this source base is `c1a8650a39f695814db67fddf79815ef249a13a5c0cc5af0b906b061c4c3a303`.

Login/Prepare creates or reopens the retained fixture instance, performs existing enrollment/recovery challenge signing as needed, then automatically verifies at most8 retained receipts serially while stopped before publishing the attached ready view. These cold proof checks are not mining attempts. Login obtains no mining job, performs no candidate nonce scan, signs no prospect admission and broadcasts no block. Only explicit Start invokes the manifest worker. A fresh empty store needs no Argon verification. Failed cold verification does not publish an attached ready view; retain data and return a fixed login/projection failure. Existing schema1 reset rules remain exact: revoke old sessions, preserve wallet/gym/payout/stores, recover the same identity, allow viewing and mining during the hold, and deny recovery-file export. Public receipt export uses View, not RecoveryExport. It does not disclose recovery material.

## 2. Constructors and ownership

Add explicit `accountpilot.NewManifest(pilot.Config)` and `pilot.NewManifestAccount(pilot.Config, pilot.ManifestAccountConfig)` constructors with concrete new controller types. Old `New`, `NewAccount`, bridge launch functions and legacy receipt methods retain their types and behavior. A small private lifecycle interface may share account/session orchestration, but the manifest engine is selected only by the new constructor, never by inspecting old data or a JSON union. New account mode rejects the optional delegated `AdmissionSigner`; its only signer is the retained published wallet under the account lease. The separate configuration seam is:

```go
type ManifestViewLease func(context.Context,
    func(gymaccount.Account, func() error) error) error
type ManifestAccountConfig struct {
    Account AccountConfig
    ViewID string
    Generation uint64
    ViewLease ManifestViewLease
}
```

Require a nonnil view lease, canonical random32 ViewID and Generation1..2^53−1. The parent generates ViewID before child construction and captures the **original** login token, account ID, generation and ViewID in a private lease closure; it never fetches a later current token to authorize an earlier operation. `ViewLease` enters the store's View lease, checks exact account/generation and the parent's active view epoch, then gives the observed Account and a combined final recheck to its callback. The child independently checks Account.ID/Generation against its immutable binding as well. Child creation/Prepare may fill the schema5 pin later, but cannot change this view binding; no setter is added. ViewID/generation are ephemeral and absent from persistence markers. The wrapper invalidates its view epoch before detach/reset/expiry and releases parent mutexes before child drain. Account/store lease -> brief parent epoch check -> brief child cache publication is the lock order; no controller/cache/outbox lock is held while acquiring the lease. Enrollment completes after construction. The captured lease permits private cold cache initialization during that exact attaching/signing_in operation after enrollment, but the parent exposes no view/child DTO until login completes. All public commands still require fully signed_in, nonbusy state. Failure/detach invalidates this epoch before cleanup; no later login can make the old closure valid again.

The concrete cross-owner child method surface is fixed as follows (types live in new `pilot/manifest_types.go`):

```go

func (*ManifestController) AccountID() string
func (*ManifestController) Prepare(context.Context) error
func (*ManifestController) SignAccountChallenge(context.Context,
    gymaccount.EnrollmentChallenge) (gymaccount.Authorization, error)

    uint64, string, string, string) error // sequence, viewID, prospectID, path
```

`LoadManifestProspects` is synchronous for attaching login; `RefreshManifestProspects` starts the same tracked core asynchronously and returns an acknowledgment, with the supplied context bound to its full lifetime. Stop/Close cancel/join it. Child Snapshot is a cheap owned local copy for the trusted parent; only the parent may expose it after its final View lease. Other child public projection/read/export methods enforce their captured ViewLease themselves; parent must not wrap those calls in a second nested account lease. Parent recovery export instead owns a RecoveryExport lease and passes its final guard into `ExportRecoveryChecked`, which does not reacquire View. `ReleaseManifestReceipt` only clears an exactly matching owned slot and can do so after expiry without authorizing any disclosure.

`accountpilot.NewManifest(Config)` returns its own `*ManifestController`, exposing Start/Stop/Close/Snapshot, existing LoginFixture/Logout/ResetFixtureAccount and the context-aware new projection/receipt/release methods above. It exposes `ExportRecovery(context.Context,string)` and `VerifyBackup(context.Context,string)` for native paths. This is the new helper's `ManifestControllerAPI`; old ControllerAPI stays unchanged. All public parent methods refuse while attaching/transitional except cheap blank Snapshot, Stop and Close. Private initial Load is called directly on the prepared child after enrollment and before final attach.

The child exclusively owns its schema5 store, version2 manifest outbox, wallet and private nodes. Use `NewManifestSessionServer`, `ManifestClient` and `ManifestWorker` from set39. A token-refresh adapter pins protocol3, exact normalized origin, `ManifestAuthorityPin` and `TransportTrustID` for its whole lifetime; each freshly constructed client must match those getters before dispatch. Tokens are never written into markers, logs, DTOs or the outbox. Preserve broadcast-before-signing, independent block/prospect thresholds, pending evidence and historical acknowledgment recovery without changing worker semantics.

Operator bounds stay explicit: service maximum jobs1000/receipts1000; outbox maximum retained records1000 and64MiB. Reaching a bound pauses/rejects as set39 specifies; no pruning or evidence loss. Preserve the actual durable authority count separately from pending/outbox count. An authority receipt can exist even when its client acknowledgment was lost.

## 3. Namespace and durable initialization

New paths, relative to the selected `LocalManifestPilot` root:

- `SLUG-MANIFEST-ACCOUNTS.json`: outer account marker, at most4096 bytes.
- `authority/`: schema1 fixture account store.
- `gyms/<canonical account_id>/`: one child root, not chosen by the webview.
- Child `SLUG-MANIFEST-PILOT.json`, `SLUG-MANIFEST-PILOT-READY.json`, `SLUG-MANIFEST-PILOT-CHAINS.json`: distinct new markers, each at most8192 bytes.
- Child `wallet/`, `primary-chain/`, `peer-chain/`, `manifest-authority/`, `manifest-outbox/`, and a bounded status file. Existing wallet/node filenames inside those directories remain unchanged.

The outer marker's ordered JSON fields are `version:1`, `mode:"local-manifest-pilot"`, `account_authority_id`, `descriptor_id`. The expected account authority comes from successful schema1 creation and is durably linked before returning success. Reopen compares it to the actual opened schema1 store. An unsigned marker inspection is not a source of trust.

The child marker's ordered fields are `version:1`, `mode`, `phase`, `account_authority_id`, `account_id`, `fixture`, `network`, `genesis`, `activation_height`, `recovery_profile`, `authority_port`, `descriptor_id`, `identity`, `payout`, `authority_pin`, `transport_trust_id`. `identity` and `payout` reuse the private scalar wallet identity/payout DTOs. `authority_pin` is the exact schema5 value, including version5/network/genesis/authority ID/descriptor ID. The origin is deterministically `http://127.0.0.1:<authority_port>`; port1..65535 is selected once and retained. A busy retained port is an error, not permission to silently change origin/trust/outbox identity.

Marker states:

| Phase | Required durable meaning |
| --- | --- |
| `new` | Exact selected account/fixture/chain/descriptor/port; identity/payout/pin zero and trust empty. Only the known empty initialization layout may exist. |
| `initializing` | Intent was synced before wallet/node/store mutation. No automatic assumption that a missing component was never created. |
| `ready` | Full independent fixture identity, payout, schema5 pin, transport ID, outbox2 configuration and both initialized chain identities agree. Every required component must exist. |

Acquire the instance lock before writing any identity marker. Files are canonical compact typed JSON plus one LF, written0600 through sync-temp/rename/directory-sync; directories0700. Bound before decode, reject duplicate/unknown/case-alias/null/noncanonical values, and compare opened-file `Stat`/`SameFile` to the initial regular-file observation. All counters/pins have exact typed validation. Status files are not authority for identity, receipt contents or balances.

Normal Stop/Quit during first initialization drains the existing bounded initialization operation to a durable ready result or explicit retained failure; it cannot abandon a committed wallet and then report clean success. On ready reopen, missing wallet/chain/authority/outbox/marker fails closed without regeneration or replacement. Unenrolled/recovery-required accounts may finish the existing enrollment challenge only after the exact retained child is ready. Enrolled accounts always require an existing ready child.

Crash recovery is deliberately conservative. If `READY` contains a complete synced ready marker and all components/pins validate, a matching `initializing` primary marker may be atomically promoted to exactly that ready marker; conflicting markers refuse. If there is no complete ready marker, retain partial initialization and return `initialization_incomplete`. In particular, a crash after `CreateManifestAuthority` but before its returned pin is durably linked is **not** repaired by calling unsigned `InspectManifestAuthority` and trusting its result. There is no UI reset/delete/recreate repair in this set. A missing outer marker with nonempty initialization data likewise refuses. This preserves evidence and distinguishes graceful drain from hard-crash lost-create-ACK recovery.

## 4. Public projection DTOs and bounds

Use separate new typed DTOs and a separate manifest protocol decoder. Do not add a `registry.ManifestRecord` alternative to legacy `Response.Receipt`, and do not widen the old Snapshot/receipt decoder to accept the new mode.

All new DTOs use snake_case JSON in declared field order, compact `json.Marshal` serialization, no free-form metadata, finite numbers and no secrets. Hash/ID fields are canonical lowercase64hex; public keys are canonical compressed66hex. Integers exposed to JavaScript must be integral and <=2^53−1; receipt sequences are1..1000. Empty collection fields are `[]`, never null. Exact round-trip response decoding rejects duplicate/unknown/case-alias/unexpected-null/trailing values. The sole explicit required null value is ManifestSnapshot.view when no authenticated ready view exists; absent optional response payload pointers are omitted, never encoded as null. Total helper frame remains256KiB including LF; request remains4096 bytes. Bound sizes/counts before copying or allocating. Error text is a fixed code, never raw node/storage/provider text.

`ManifestViewPin` fields: `version` uint32=1; `view_id` lower64hex; `account_authority_id`, `account_id`; `generation` uint64; `authority_pin` typed `registry.ManifestAuthorityPin`; `authority_origin` string<=256; `transport_trust_id`. `view_id` is fresh random32 per successful attached login/view epoch, is not a bearer credential, and changes on reattach/reset/login. It prevents stale async UI/native results from being applied to another view; trusted session/account checks remain mandatory.

`ManifestProspectSummary` fields: `sequence` uint64; `id`, `work_hash`; `born_at_ms`, `accepted_at_ms` int64; `name` typed `fightermanifest.Name`; `physical` typed `fightermanifest.Physical`; `style`, `rarity`; `talent_budget` int; `attributes` typed `fighter.Attributes`; `descriptor_id`, `manifest_digest`, `portrait_digest`; `eligibility_mode` string. Name fields use the frozen table values (each<=64 ASCII bytes, display<=129); style/class/stance/rarity/eligibility are their existing closed values. The helper establishes exact physical/attribute equality to the validated manifest/DNA once during live/cold projection. Polling/native/frontend decoders enforce closed types/bounds/pins and revision consistency; they do not regenerate the manifest or repeat proof verification on every Snapshot. `id` is the full stable prospect ID and the UI key; names may duplicate. Birth and eligibility are original receipt history, not a current canonicality assertion.

`ManifestProjection` fields: `state` (`idle|loading|ready|failed|cancelled`), `error` (`""|projection_unavailable|projection_corrupt|projection_cancelled`), `revision` uint64, `through_sequence` uint64, `has_older` bool, `complete_recent` bool, `items` []ManifestProspectSummary length0..8. Items are newest-first. `through_sequence` is the greatest cached receipt sequence (0 when empty), not a contiguous-history claim. `has_older` is true when accepted_count exceeds cached item count; `complete_recent` is true only in projection state ready when the cache contains every sequence from max(1,accepted_count−7) through accepted_count (empty range for count0). It is false for idle/loading/failed/cancelled or a null view. A live event may populate a partial recent page; the UI labels any remaining historical gap. No paging/import API is added. The authority retains all earlier receipts. `revision` increments after each successful atomic page/event publication; account/view changes clear it to0.

`ManifestSnapshot` fields: `version:1`, `mode:"local-manifest-pilot"`; the same explicitly declared public scalar mining/wallet/backup status fields as current Snapshot (`state`, `attempts`, `hashes_per_second`, `height`, `pending`, `last_error`, `recovery_error`, wallet state/height/payout/gym key+ID/amounts and backup state/phase/error); `account` typed AccountSnapshot; `view` *ManifestViewPin; `accepted_count` uint64; `projection` ManifestProjection. It has no legacy `prospects` or `prospect_count`. Signed-out/busy/expired/failed account projections expose null view, zero account-specific counts/amounts, blank wallet identity and no candidate items. Snapshot copies cached values under the same original View lease, exact account/generation/view/child checks and final recheck before returning. Do not reuse the old check-then-copy-outside-lease snapshot path. RecoveryExport availability may be probed separately before this final View capture using the same token and matching account/generation; never nest account leases. On final View failure clear all account-specific output. Snapshot reads cached values only, apart from bounded existing account capability validation; it never reads a proof, hashes Argon, regenerates a manifest or renders SVG.

`ManifestPortrait` fields: `version:1`, `view` ManifestViewPin, `sequence`, `id`, `manifest_digest`, `portrait_digest`, `svg` string. SVG is exact renderer ASCII,1..32768 bytes, unchanged by wrapping/encoding. `ManifestReceipt` fields: `version:1`, `view` ManifestViewPin, `record` typed `registry.ManifestRecord`. The contained canonical record obeys `registry.MaxRecordSize` (65536 bytes). Each whole response must independently fit the256KiB cap; no array of full receipts or SVGs is returned.

## 5. Verified live notification, cold scheduling and cache

### Minimal worker extension

Add the following optional notification surface without changing any set39 constructor or persistent format:

```go
type ManifestReceiptObserver func(context.Context, registry.ManifestRecord) error
func NewManifestWithObserver(config ManifestConfig, authority ManifestAuthority,
    node Node, signer Signer, outbox *ManifestOutbox,
    observer ManifestReceiptObserver) (*ManifestWorker, error)
```

`NewManifest` retains its exact signature/behavior and delegates privately with a nil observer. A nil observer on the new constructor is equivalent. There is no setter, public trusted-JSON/projector shortcut, persisted observer state or change to outbox version2. This narrowly touches the new manifest worker runtime and adds focused observer tests; the old worker and constructors are unchanged.

Invoke the observer synchronously on the existing single Run goroutine only when a pending admission has returned a valid success, the worker has performed its own full production proof verification and complete receipt/config binding checks, and the outbox has successfully synced the accepted receipt. The successful `outbox.update` must have returned and released its mutex. An uncertain/failed write, rejected/malformed response, block-only win or already-terminal entry produces no event. Both newly inserted and successfully recovered historical receipts qualify after this exact validation/durable transition. Do not emit by iterating persisted terminal outbox JSON at startup.

The callback receives a new bounded owned record, with a separate copy of every reference-bearing field (currently proof MerkleBranch), never the worker entry or outbox cache's backing data. Validate its encoded bound before copying. It may retain/mutate its own copy without changing journal evidence. No worker/status/outbox lock or service/account lease is held during the callback. At most one callback is active; no callback goroutine, queue or concurrent hash is introduced. It therefore runs between attempts, after block-first handling and durable admission, without another Argon calculation. The callback must not reenter Run, join/Close the worker or close dependencies.

The observer is an ephemeral notification, not exactly-once delivery: a crash/cancel after durable save may omit it, and there is no retry/dedup side effect in the worker. If Run context is already cancelled after save, skip the notification; if cancellation arrives during it, pass that same context and wait for it to return. A returned error or panic stops Run with a fixed observer error/status (no panic payload), leaves the accepted receipt untouched and does not convert admission into failure/unknown or resubmit it. Proposed exported sentinel is `ErrManifestObserver`; Status.LastError is `observer_unavailable`. Stop/Close joins the callback as part of normal Run drainage. Cold verified authority reads recover any missed notification.

The desktop's observer owns the immutable per-run view/pin and original View-session reference. It checks cancellation, cheaply regenerates the manifest from the verified WorkHash/DNA, validates the compiled descriptor and exact stored static digests, then reacquires the same current View credential. Under that lease it checks account/generation/view/child/pins again and publishes the owned summary/manifest/receipt atomically with only a brief cache mutex. It performs no node/provider/file I/O, no signing, no store/outbox access and no Argon. It may generate the bounded portrait lazily as below. Expired/replaced/cancelled view discards notification without exposing data; known cancellation/transition is not a projection-corruption error. A true descriptor/digest mismatch clears the view cache and returns the fixed observer failure to stop mining. The parent session-expiry/logout path still cancels Run.

Merge a valid live receipt by full prospect ID/sequence, require any already-cached version to be exactly identical, and retain the highest8 sequences. Same ID/different sequence or same sequence/different ID is corruption, not replacement. Exact repeats are idempotent and need not increment revision. A late recovered historical callback fills a missing recent sequence or is ignored if it is below the retained newest8; never perform hidden Argon reads to fill a gap while mining. Duplicate display names are allowed. `accepted_count` is the greatest authenticated count observed for this attached view: max(previous count, a fully verified receipt sequence, same-pin Store.Info Records). A stale ticker sample must never lower it. Count and cache/revision/coverage are published under the same brief mutex; completeness is relative to this observed count, not an assertion that no later concurrent admission exists. A metadata increase alone may change complete_recent to false. Do not assume callback count equals receipt count. Each changed valid page increments revision and supplies the new candidate immediately to the next cheap Snapshot. Missing older notifications do not hide new ones; `complete_recent` remains false until the latest required range is available. No data from a failed/lost HTTP response is published before durable verified recovery.

### Cold verification and cache

One child operation gate owns initialization, mining, backup verification, enrollment signing and cold projection. They cannot overlap. The live notification above is part of the mining operation, not another concurrent task. Start refuses while projection/backup/initialization is active. Cold load runs automatically once after Prepare and enrollment on each successful login/reopen, still stopped and while the parent is attaching. Start remains unavailable until it completes. The same core is used by an explicit stopped, ready, View-authorized Refresh for retry/incomplete history; that public operation runs asynchronously so Stop/logout/Quit can cancel it and acknowledgment does not imply successful verification. Stop and periodic polling never implicitly start a cold refresh.

Refresh first captures the exact active view/session/child identity and checks View. Then, outside the account lease and outside mining, take a stable metadata count N from the exclusively owned schema5 store. Read the last min(N,8) records in sequence order using `ListManifestAdmissions(after,1)` in a serial loop, checking cancellation before and after every call. This uses at most8 production Argon verifications and bounds unavoidable cancellation drain to the current call, not an unbounded page/history. There are no verification goroutines or parallel hashes. Require exact consecutive sequence, gym/account key, job authority/descriptor, stored context and regenerated static binding. Reconstruct each manifest from the exact work hash/full verified DNA with the pinned descriptor. Compare both stored static digests. No current policy/clock/node check rewrites or rejects authentic historical receipt history.

Build a complete temporary page; publish no partial page. After all work, reacquire the same original View credential, require unchanged view/account/generation/child/pins, call final recheck and publish the immutable owned cache while that lease still excludes reset. If any step fails/cancels or the account changed, discard the temporary page. Refresh invalidates the prior page before work begins, so a failed verification cannot leave a new-looking old page presented as successful. Status may say failed/cancelled, but items/receipt/image cache are empty.

While mining, automatic live notifications populate/advance the same verified cache; polling only reads it and cheap cached worker/wallet/count status. Cold reopen verification runs automatically during stopped login; an explicit stopped refresh handles exceptional incomplete history or retry. When `complete_recent` is false, say “Some accepted candidates are still syncing.” A stopped manual refresh is a historical recovery action, not the ordinary path for new arrivals; new validated arrivals continue to appear automatically. Do not infer trusted admission from arbitrary outbox rows. A stopped explicit refresh loads the latest full bounded page.

Cached public reads use the captured original View authorizer, not just a local account-ID comparison. Portrait retrieval copies a selected cached manifest/pin under initial View authorization, releases the lease before bounded rendering, then reacquires the same original View lease and calls its final recheck while verifying the selected ID/digests still belong to the current view before returning. A cached receipt preflight similarly creates its export pin and returns the typed owned copy only under the same-view final View check. Clear outputs on any error; never return partially populated DTOs. Release leases before writing to stdio/browser/socket, which may block. Only current verified page members can supply details or receipt export. A request for an uncached sequence returns `projection_required`/`prospect_unavailable`, never a hidden cold hash during mining. Lazy portrait generation may run while mining because it uses only owned verified manifest data and bounded integer rendering, not Argon. It verifies the resulting domain-separated digest before release. Run at most one lazy render at a time; no queued work. Retain at most8 manifests,8 page receipts and8 SVGs, plus one separately pinned public export receipt as described below; combined byte accounting cap1MiB, SVG subtotal<=262144, canonical page-receipt subtotal<=524288, export-slot receipt<=65536, canonical manifest subtotal<=65536. Copy before returning; no callbacks or returned slices can mutate cached proof branches or page state. Cache is memory-only and keyed by the complete view/pins plus sequence/ID/digests, never by display name.

Clear all caches and invalidate view_id before logout/reset/account transition/Close/session expiry or a detected authority/descriptor/origin/trust mismatch. Cancel and join any current verification/render before closing the store; finish an already-started Argon call. Reattachment always performs a fresh automatic bounded cold load, even for the same fixture. Polling must not disclose the former account's page while transition state is busy. A public image already delivered cannot be remotely erased; the application removes its DOM/cache references promptly and makes no revocation-of-copied-data claim.

## 6. Typed helper/native API and export

Add `ServeManifest`, `ManifestRequest`/`ManifestResponse`, and an explicit manifest bridge/`LaunchManifests` path. Shared framing/process-lifetime helpers may be private, but legacy decoders and methods retain their accepted shapes. New responses are `{id,ok,snapshot?,portrait?,manifest_receipt?,error?}` with exactly one success payload and no success payload on error. All control ACKs contain a ManifestSnapshot. Keep one in-flight bridge request, bounded reader queue and existing EOF/blocked-output drain behavior.

New `ManifestRequest` fields in order are `id`, `command`, `sequence,omitempty`, `path,omitempty`, `fixture,omitempty`, `view_id,omitempty`, `prospect_id,omitempty`; required presence and forbidden-field validation are command-specific, including explicit zero/empty/null spellings. IDs remain1..2^53−1. New helper commands are the existing explicit control/account/recovery commands plus `refresh_manifest_prospects`, `manifest_portrait`, `manifest_receipt`, `export_manifest_receipt`, and `release_manifest_receipt`. For the three sequence commands require sequence1..1000; other commands forbid it. `release_manifest_receipt` takes only the captured `view_id` and `prospect_id` (no sequence/path), returns a snapshot ACK, and cannot release a different pinned selection. `export_manifest_receipt` additionally requires native-chosen absolute path<=1024 UTF8 bytes (no NUL/CR/LF), captured `view_id` and expected full `prospect_id`. Native-only recovery path commands retain current rules. Each command rejects inapplicable fields. No arbitrary proof, SVG, manifest, receipt JSON, key, authority ID, callback, URL or account-directory parameter is accepted.

Webview methods are `Gym.Mode()`, existing controls routed by explicit mode, `Gym.ManifestSnapshot()`, `Gym.RefreshManifestProspects()`, `Gym.ManifestPortrait(sequence)`, and `Gym.ExportManifestReceipt(sequence)`. Old `Gym.Snapshot()`/`ExportReceipt()` remain old typed routes and refuse in new mode; new methods refuse in old modes. The webview provides only a bounded sequence for portrait/export, never a filesystem path or trusted pin. The new frontend checks native immutable mode once and uses only the manifest typed snapshot API. Do not make a permissive union normalizer. Existing index.html/app.js and their tests keep their current calls unchanged.

Native receipt export holds the existing native action/dialog mutex that also excludes Login/Logout/Reset and overlapping export/backup dialogs. Obtain a typed cached ManifestReceipt under current View as preflight; the helper pins one owned public export receipt in a separate bounded slot, so new live arrivals cannot evict the selection during the dialog. A new preflight replaces that one slot. Capture its view_id/ID/sequence/pins, and open SaveFile with a public-candidate-receipt message and `slug-candidate-receipt-<sequence>.json` default. Cancel returns empty string. After selection, send `export_manifest_receipt` with the captured selectors and native path. The helper reacquires **the same** active View/session/child and requires exact pinned export-slot receipt equality/pins and final recheck before no-overwrite atomic file commit. It writes the canonical typed registry.ManifestRecord plus LF; it returns only the new typed snapshot/ACK. This final helper-owned write closes the dialog-time expiry/reset gap and uses a checked exclusive publication path. Existing `atomicBytes` overwrites by rename and must not be reused unchanged: final public receipt/recovery-file publication must refuse an existing destination, even if it appears after the dialog. Sync file and pinned parent directory; keep protected-root checks. It never holds an account lease while waiting for the native dialog. Any late cancellation/write uncertainty returns an honest fixed failure and does not claim no file could have been committed. The helper consumes the slot after successful export; native cancellation/error performs a bounded best-effort `release_manifest_receipt` and account invalidation always clears it. Slot absence/mismatch refuses with no cold verification. Success native return is `Receipt saved.`

Public receipt export is permitted during the reset hold with a current View session; recovery file export remains denied. Exporting public evidence grants neither ownership nor current chain status. Protect the new account root and all three prior default roots, never overwrite an existing file, and do not accept a path from JavaScript. The native shell must not cache a receipt across an account/view change or use the active account at the *end* of a dialog as a substitute for the captured account.

New stable operation errors are `projection_unavailable`, `projection_corrupt`, `projection_cancelled`, `projection_required`, `prospect_unavailable`, `portrait_unavailable`, `manifest_receipt_unavailable`, `initialization_incomplete`, plus applicable existing fixed control/account/export errors.
